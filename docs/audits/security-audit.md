# تدقيق أمني أساسي — Essential Security Audit

التاريخ: 2026-11-01 · النطاق: مصادقة/تفويض، IDOR، رفع ملفات، Rate limiting، جلسات، أسرار، سجلات تدقيق، تبعيات.

## ما تم فحصه وإصلاحه

### 1. IDOR — تم إصلاح 4 ثغرات فعلية
اختبار سلوكي بجلسات مدير مقابل مندوب:

| المسار | قبل | بعد | الإصلاح |
|--------|-----|-----|---------|
| `GET /api/v1/expenses/{id}` لأي مستخدم | 200 | 403 | `view_all_expenses` أو المالك فقط |
| `GET /api/v1/custodies/{id}` لأي مستخدم | 200 | 403 | `view_all_records`/`manage_treasury` أو وكيل العهدة |
| `GET /api/v1/users/{id}` لأي مستخدم | 200 | 403 | `manage_users` أو المستخدم نفسه |
| `GET expenses/{id}/download-attachment` بصلاحية `spend_money` فقط | ثغرة | محمي | نفس سياسة عرض المصروف |

### 2. رفع الملفات
- **التحقق سليم أصلًا**: `mimes:pdf,jpg,jpeg,png,doc,docx|max:2048` (قائمة بيضاء + 2MB).
- **التخزين**: كان على القرص `public` (الملف قابل للوصول مباشرة عبر `/storage/...` بمعرفة الرابط). **تم التحويل للقرص الخاص** للرفعات الجديدة، ومسار التنزيل يقرأ الخاص مع سقوط للقديم العام (توافق خلفي).
- التنزيل يمر الآن بالتفويض أعلاه — لا تجاوز عبر رابط مباشر للملفات الجديدة.
- `downloadAttachment` يحل المسار عبر `storage_path` مع القيم المخزنة فقط (لا إدخال مستخدم في المسار).

### 3. Rate limiting
- تسجيل الدخول: `throttle:login` بقابلية ضبط عبر `LOGIN_THROTTLE_MAX` (الافتراضي 10، المحلي 120).
- **مضاف**: خنق عام لكل `/api/v1` — `API_THROTTLE_MAX` طلب/دقيقة لكل مستخدم+IP (الافتراضي 120، موثق في `.env.example`).

### 4. الجلسات وCSRF
- CSRF مطبق على كل `/api/v1` ما عدا `auth/login` (أول طلب بدون جلسة — بديلًا عنه خنق المعدل). ✅
- `http_only=true`، `same_site=lax` ✅. انتهاء الجلسة يعيد 401 JSON للـ SPA بدل التحويل ✅.
- **مطلوب في الإنتاج**: `SESSION_SECURE_COOKIE=true` (HTTPS) + تقييم `SESSION_LIFETIME` (حاليًا سنة كاملة).

### 5. الأسرار
- `.env` مستثنى من Git ✅، لا مفاتيح مكتوبة في الكود ✅، `APP_KEY` موجود ✅.
- `.env.example` موثق بكل متغير جديد.

### 6. سجلات التدقيق
- `ActivityLogService` مستخدم في 7 متحكمات للعمليات المالية/التشغيلية الحرجة (قبول عهدة، صيانة، مصروفات…).
- **توصية**: تسجيل محاولات تسجيل الدخول الفاشلة وتغيير الأدوار في `users.assign-roles`.

### 7. تبعيات
- npm (production): **0 ثغرات** ✅.
- Composer: كانت **47 تحذيرًا في 12 حزمة** (guzzle, laravel/framework, symfony/*) — **تم التحديث إلى 0 تحذيرات** مع بقاء التطبيق يعمل (health/login/API/routes كلها مؤكدة).

## توصيات إنتاجية متبقية
1. `SESSION_SECURE_COOKIE=true` و`APP_DEBUG=false` على الخادم الحقيقي.
2. HTTPS إجباري (فروض HSTS عند الاستضافة المشتركة إن أمكن).
3. إضافة تسجيل لمحاولات الدخول الفاشلة وassign-roles.
4. مراجعة `SESSION_LIFETIME` (سنة) — تقليلها أو ربطها بخيار "تذكرني" فعلًا.
