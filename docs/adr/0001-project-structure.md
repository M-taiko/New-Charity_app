# ADR-0001: هيكل المشروع — Laravel + Angular SPA على استضافة PHP فقط

## الحالة
مقبول (2026-11)

## السياق
الاستضافة المشتركة تدعم PHP فقط (بدون Node runtime في الإنتاج). واجهة Blade قائمة تعمل، والمطلوب واجهة حديثة دون كسر القديمة أو إعادة البنية التحتية.

## القرار
- Laravel 12 يظل التطبيق الخلفي الوحيد: مسارات Blade كما هي على `/`، وواجهة الـ SPA تُخدم كملفات ثابتة من `public/app` تحت `/app` فقط.
- الـ SPA (Angular 20) يُبنى محليًا بـ `ng build` ثم يُنسخ إلى `public/app` عبر `scripts/pack.mjs` — لا حاجة لـ Node على الخادم.
- الـ API الموحد للـ SPA: `routes/api_v1.php` تحت بادئة `/api/v1` بوسيط `web` (جلسة Cookie نفسها، لا CORS ولا توكنات).
- الـ SPA fallback محصور في `/app/*` (`web.php`): أي مسار آخر غير معروف = 404، مع حماية traversal عبر `realpath`.
- أثناء الترحيل: Blade هي الافتراضي، و`/app` هو الواجهة الجديدة — التعايش لا الإحلال.

## العواقب
- ✅ نشر بملفات PHP فقط؛ لا تغيير على استضافة قائمة.
- ✅ جلسة واحدة للوجهتين (Blade/SPA) بلا تكوين CORS.
- ⚠️ نُسخ يدوي للـ bundle (pack.mjs) — يُدمج في سكربت إصدار واحد (`build` ثم `pack`).
- ⚠️ حجم مستودع أكبر قليلًا (public/app) — مقبول لغياب CI/CD على الاستضافة.
