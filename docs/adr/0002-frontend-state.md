# ADR-0002: إدارة الحالة في الواجهة — Signals + resource()

## الحالة
مقبول (2026-11)

## السياق
SPA بـ Angular 20 (signals، OnPush، standalone). بيانات كلها من `/api/v1` وتتطلب تحميلًا غير متزامن مع حالات loading/error/empty لكل صفحة.

## القرار
- **الإشارات (Signals) فقط** للحالة المحلية والسيرفر معًا — لا NgRx ولا Redux ولا RxJS state.
- تحميل السيرفر عبر `resource()` بقراءة الباراميترات داخل الـ loader (وليس `params:` كدالة) + `reload()` يدوي:
  - السبب (موثق بالتجربة): في Angular 20.3، تغيّر هوية كائن `params` يُسقط القيمة القديمة فورًا ويعيد بناء العرض — جدول كامل يُدمّر ويُبنى عند كل فرز/ترحيل. القراءة داخل الـ loader مع `reload()` تحافظ على القيمة أثناء التحديث.
- **قراءة `resource.value()` على مورد مخطئ تُرمي استثناء** يوقف العرض — لذلك كل صفحات التفاصيل تمر عبر `safeValue()` (computed يعيد null عند الخطأ) مع فرع "غير موجود".
- مكوّن جدول واحد `DataTableComponent` يمتلك: الفرز (سيرفر عبر sortable maps الخلفية)، الفلترة (محليًا على النص المعروض: خام + تنسيق العملة + dd/mm/yyyy + تسميات التعداد)، تغيير عرض الأعمدة وسحبها وحجم الصفحة — محفوظة في localStorage بمفتاح `مسار/مفتاح` لكل صفحة.

## العواقب
- ✅ نمط واحد بسيط لكل الصفحات، بلا متاجر إضافية.
- ✅ الجدول يبقى نفس عقدة DOM عند التحديث (حالة الفرز/التمرير محفوظة).
- ⚠️ `resource()` تجريبي — إعادة تقييم عند ترقية Angular كبرى.
