# ADR-0004: المصادقة والتفويض — جلسة واحدة + أبواب حسب الدور

## الحالة
مقبول (2026-11)

## السياق
نظام مالي متعدد الأدوار (مدير، محاسب، مندوب، باحث اجتماعي، مشرف) مع Blade وSPA على نفس النطاق.

## القرار
- **المصادقة**: جلسة Laravel (كوكيز http_only، same_site=lax) للوجهتين معًا. لا توكنات في localStorage إطلاقًا.
- **الأدوار**: spatie/laravel-permission بأدوار عربية مطابقة للأصل (مدير/محاسب/مندوب/باحث اجتماعي/مشرف) — النقل من قاعدة الإنتاج كما هو.
- **التفويض خلفيًا**: أبواب `Gate::define` صريحة (view_all_records، view_all_expenses، manage_users، manage_settings…) + فحوصات `abort_unless` في متحكمات API للمسارات الحرجة — لا فحوصات في الواجهة كضمان أمني.
- **الواجهة**: تخفي ما لا يملكه الدور (قوائم/أزرار) وتعتمد على `abilities` القادمة من `/auth/login` — تحسين تجربة فقط، الأمان في الخلفية دائمًا.
- كل مسار `{id}`: تفويض ملكية أو دور — موثق ومختبَر (انظر security-audit).

## العواقب
- ✅ سياسة واحدة قابلة للتدقيق، وتوافق خلفي كامل مع Blade.
- ⚠️ أسماء الأدوار عربية — مرتبطة ببيانات الإنتاج؛ أي إعادة تسمية تتطلب ترحيل بيانات.
- ⚠️ الجلسة الطويلة افتراضيًا (سنة) — موصى تقليصها في الإنتاج (انظر توصيات التدقيق).
